## 目标回顾

`v0.6.2` 的目标不是把所有内部调用统一改成 Dubbo，而是只选一条同步、稳定、强类型、业务语义清晰的链路做 RPC 对比学习：

```text
task-service -> java-demo-app 用户校验
```

通知创建链路依然保留 OpenFeign，后续继续按既定路线在 `v1.0 MQ` 再演进为异步事件，不在本版提前改动。

## 最终实现

### 1. 调用边界

| 调用方 | 被调用方 | 本版主路径 | 说明 |
|---|---|---|---|
| `task-service` | `java-demo-app` | Dubbo RPC | 只负责创建/更新任务时的负责人用户校验 |
| `task-service` | `notification-service` | OpenFeign | 保持通知创建同步调用语义，留待后续 MQ 改造 |
| React / Vue / 外部客户端 | Gateway / REST API | HTTP | 对外入口保持不变，不引入用户可见变化 |

### 2. 契约与模块

| 模块/文件 | 实现结果 |
|---|---|
| `backend/rpc-api` | 新增共享 RPC 契约模块 |
| `DubboAttachmentConstants` | 只保留 `requestId` 附件键 `java-demo-request-id` |
| `UserRpcService` | 最终使用 `getUserSummary(Long userId)` 作为最小稳定契约 |
| `UserSummaryRpcResponse` | 只暴露任务校验真正需要的 `id`、`username`、`status` |

### 3. Provider 与 Consumer 落地方式

| 位置 | 实现结果 |
|---|---|
| `backend/app/src/main/java/com/example/javademo/app/rpc/UserRpcServiceImpl.java` | 作为 Dubbo provider 暴露用户校验能力 |
| `backend/task-service/src/main/java/com/example/javademo/task/config/DubboReferenceConfiguration.java` | 通过桥接 Bean 暴露 Dubbo consumer 代理 |
| `backend/task-service/src/main/java/com/example/javademo/task/client/UserServiceClient.java` | 业务层继续只依赖包装层，由包装层完成 Dubbo 调用、异常映射和日志 |
| `backend/task-service/src/main/java/com/example/javademo/task/client/feign/UserFeignClient.java` | 已删除，不再保留用户校验 Feign 主实现 |
| `backend/task-service/src/main/java/com/example/javademo/task/client/feign/NotificationFeignClient.java` | 继续保留，用于通知创建 |

### 4. 实际业务语义

| 项目 | 实现结果 |
|---|---|
| 用户校验方法 | `UserRpcService#getUserSummary(Long userId)` |
| “用户不存在”表达方式 | provider 返回 `null` |
| “用户不存在” consumer 语义 | `BusinessException.badRequest("Assignee user does not exist")` |
| “RPC 调用失败” consumer 语义 | `BusinessException.downstream("User service is unavailable")` |
| 既有业务边界 | 保持与原 `getUser(id)` 行为一致，即“存在且未逻辑删除即可” |

## 实际实现与原计划差异

| 项目 | 原计划倾向 | 最终实现 | 原因 |
|---|---|---|---|
| RPC 方法 | `existsActiveUser` 或 `getUserSummary` 二选一 | 选择 `getUserSummary` | 既能做存在性校验，也保留未来任务详情展示最小扩展空间 |
| 用户不存在语义 | 可返回布尔值或异常 | 返回 `null` | 让 consumer 明确区分“业务不存在”和“RPC 调用失败” |
| Feign 回退 | 可保留临时回退 | 未保留用户校验 Feign 主实现 | 避免同一主链路长期双实现 |
| Dubbo 引用方式 | 直接注入远程代理 | `@DubboReference` + 桥接 Bean | 兼顾 Dubbo 3.3 兼容性与测试替换能力 |

## 已知注意事项

| 问题 | 说明 | 处理方式 |
|---|---|---|
| Dubbo 3.3 `ReferenceBean` API 与旧写法不一致 | 直接手写 `ReferenceBean` 容易踩版本兼容坑 | 改为 `@DubboReference` + Spring 桥接 Bean |
| `UserRpcService` 可能出现重复候选 Bean | 既有 Dubbo 代理又有测试替身时容易注入歧义 | 桥接 Bean 固定命名为 `userRpcServiceBridge`，业务层使用 `@Qualifier` |
| 自动化测试误连真实 Dubbo/Nacos | 测试启动阶段不应依赖外部注册中心 | `DubboReferenceConfiguration` 增加 `@Profile("!test")`，测试中使用 `@MockBean(name = "userRpcServiceBridge")` |
| Vue 标准 `dist` 目录文件锁 | Windows 环境可能出现 `EPERM` | 使用备用输出目录 `dist-v0_6_2_check` 做构建回归 |
| Nacos 发布 YAML 编码限制 | Windows 下当前 Nacos Config 解析链路要求待发布 YAML 保持 ASCII-only | 中文说明写在 README、PROGRESS、milestone 或 notebook，不写进待导入 YAML |

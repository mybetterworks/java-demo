# v0.9 MinIO

状态：已完成。

完成时间：2026-06-07，Asia/Shanghai。

## 目标

引入 MinIO，支持用户头像、任务附件或通知附件上传，验证对象存储在微服务系统中的基本用法。

## 新增能力

文件对象存储。本版本选择“用户头像 + 任务附件”作为最小可运行闭环，通知附件暂不纳入，避免在同一个 milestone 中同时扩大通知业务模型和文件存储模型。

| 类别 | 技术 |
|---|---|
| 文件系统 | MinIO |
| 后端 | 文件上传接口 |
| 前端 | 头像上传组件 |

|---|---|
| Bucket 初始化 | 创建用户头像和任务附件 bucket |

## 存储边界

文件内容保存在 MinIO，MySQL 只保存业务元数据和 object key。

| 数据 | 存储位置 | 说明 |
|---|---|---|
| 头像文件内容 | MinIO `java-demo-avatars` bucket | object key 由后端生成，前端不可提交或指定 |
| 头像 object key | `java_demo.user.avatar_object_key` | 只服务端使用，不返回前端 |
| 头像访问 URL | `UserProfileResponse.avatarUrl` | 返回 `/api/users/public/avatars/{userId}?v=...` 代理地址，用版本参数帮助浏览器刷新缓存 |
| 附件文件内容 | MinIO `java-demo-task-attachments` bucket | object key 按任务、用户、时间和随机 UUID 生成 |
| 附件元数据 | `java_demo_task.task_attachment` | 保存任务 ID、上传人、原始文件名、contentType、sizeBytes、bucket、objectKey、createdAt |
| 附件下载 | 后端代理 | 下载接口需要 JWT；前端通过 fetch Blob 下载，避免 `<a>` 直链丢失 Authorization header |

## 接口

| 能力 | 方法与路径 | 权限 | 说明 |
|---|---|---|---|
| 上传当前用户头像 | `POST /api/users/me/avatar` | JWT | `multipart/form-data`，字段名 `file`；允许 PNG、JPEG、WebP，默认最大 2MB |
| 公开读取用户头像 | `GET /api/users/public/avatars/{userId}` | 公开 | 后端按用户当前 `avatarObjectKey` 代理读取 MinIO，不允许浏览器传入 object key |
| 上传任务附件 | `POST /api/tasks/{taskId}/attachments` | JWT | `multipart/form-data`，字段名 `file`；允许 PNG、JPEG、WebP、PDF、TXT、ZIP，默认最大 10MB |
| 查询任务附件 | `GET /api/tasks/{taskId}/attachments` | JWT | 返回附件元数据，不返回 object key |
| 下载任务附件 | `GET /api/tasks/{taskId}/attachments/{attachmentId}/content` | JWT | 后端代理读取 MinIO 并返回文件流 |
